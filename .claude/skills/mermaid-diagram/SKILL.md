# /mermaid-diagram

`src/` 디렉토리를 분석해 (1) 컴포넌트 간 의존성 그래프와 (2) 상태 흐름을 Mermaid 다이어그램으로
시각화한 자기완결형 HTML 파일을 생성하고, 생성 직후 브라우저로 바로 연다.

## 언제 쓰나

- 사용자가 프로젝트 구조/아키텍처를 시각화해달라고 할 때
- 컴포넌트 의존 관계나 상태 흐름을 한눈에 파악하고 싶을 때
- `/mermaid-diagram`으로 직접 호출되었을 때

## 작업 절차

### 1. 분석
`src/` 하위 모든 `.ts`/`.tsx` 파일을 읽고 import 문을 기준으로 의존 관계를 추출한다. 파일을
역할별로 분류한다 (예: 진입점, 화면 컴포넌트, Context/전역 상태, API 모듈, 타입 정의 등).
분류 기준은 프로젝트 구조에 맞춰 유연하게 적용하고, 특정 프로젝트(예: 노트 앱)의 구조를
하드코딩해서 가정하지 않는다 — 실행할 때마다 실제 파일 목록을 다시 스캔한다.

### 2. 컴포넌트 의존성 그래프
Mermaid `flowchart` (`graph TD` 등)로 작성한다.
- 노드 모양으로 역할을 구분한다: 화면 컴포넌트=사각형, Context/전역 상태=원통형(`[(...)]`),
  API 모듈=사다리꼴(`[/.../]`), 타입 정의=점선 테두리.
- 화살표 스타일로 관계 종류를 구분한다: "렌더링(하위 컴포넌트로 사용)"은 실선, "훅으로 상태만
  구독"은 점선.
- 노드/서브그래프 라벨은 프로젝트의 UI 텍스트 언어 관례(예: 한국어 프로젝트면 한국어)를
  따른다.

### 3. 상태 흐름 다이어그램 (가능한 경우 추가)
전역 상태(서버 상태)와 로컬 UI 상태를 구분해서 표현한다.
- 서버 상태: API 호출 → 전역 상태(Context/store) 갱신 → 이를 구독하는 컴포넌트 재렌더링
  흐름을 `flowchart` 또는 `sequenceDiagram`으로 표현.
- UI 전용 상태(선택 상태, 모드 플래그 등): 어느 컴포넌트가 소유하고 어디로 props/콜백으로
  내려가는지 표현.
- 전역 상태를 관리하는 계층이 없는 프로젝트라면 이 단계는 생략 가능.

### 4. HTML 생성
- mermaid.js를 CDN `<script>` 태그로 포함한 단일 자기완결형 HTML 파일로 만든다 (별도 빌드
  과정 없이 파일을 바로 열어서 렌더링되어야 함).
- 다이어그램 2개(의존성 그래프, 상태 흐름)와 간단한 범례를 포함한다.
- 다크/라이트 모드 등 부가 스타일은 과하지 않게, 가독성 중심으로 최소한만 적용한다.

### 5. 저장
결과 HTML을 `docs/architecture/index.html`로 저장한다. 디렉토리가 없으면 생성한다.

### 6. 브라우저로 열기
생성이 끝나면 터미널에서 바로 기본 브라우저로 파일을 연다. 실행 환경을 감지해서 적절한 명령을
사용한다.
- WSL: `wslview <경로>`가 있으면 사용, 없으면
  `explorer.exe "$(wslpath -w <경로>)"`.
- macOS: `open <경로>`.
- 순수 Linux: `xdg-open <경로>`.
- Windows 네이티브 셸: `start <경로>`.

브라우저 실행은 로컬 파일을 여는 것뿐이므로 별도 확인 없이 바로 실행해도 된다.
