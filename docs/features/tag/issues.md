# 태그 기능 이슈 분해

`prd.md`(개요/사용자 스토리/ADR)를 기반으로, 수직 슬라이싱 원칙에 따라 이슈를 나눴다. 각
이슈는 타입/유틸/컴포넌트/상태/API를 아우르는 하나의 완결된 사용자 행동 단위이며, 완료 시
사용자가 직접 확인할 수 있는 결과물을 만든다. "타입만 추가", "유틸 함수만 작성" 같은 수평
계층 단위의 이슈는 만들지 않았다 — 필요한 계층 변경은 그 계층을 실제로 쓰는 첫 이슈에
포함시켰다.

이 문서는 **태그 기능 구현 이슈만** 다룬다 (디자인 시스템, 훅 등 다른 작업은 범위 밖).

> 이전 버전에서는 "저장 전 취소 시 태그 변경 폐기"를 별도 이슈(TAG-4)로 뒀었다. 그런데 그
> 동작은 TAG-1/TAG-2가 "저장 버튼을 눌러야만 서버에 반영"되는 로컬 상태로 설계된 데서 자연히
> 따라오는 결과라 별도 구현 없이 확인만 하면 되는 얇은 이슈였다. 그래서 취소 시나리오를
> TAG-1/TAG-2/TAG-4(신규 생성)의 완료 조건에 각각 흡수했다.

## 이슈 목록 및 순서

1. TAG-1: 편집 중인 노트에 태그 추가 (편집 모드 한정)
2. TAG-2: 편집 중인 노트에서 태그 삭제
3. TAG-3: 노트 상세 화면에서 태그 목록 조회 (기존 노트 포함)
4. TAG-4: 새 노트 생성 시 태그와 함께 저장 (생성 모드에 `TagInput` 노출 시작)

TAG-2~4는 TAG-1에서 만드는 `TagInput` 컴포넌트/`src/utils/tags.ts`를 재사용하므로, TAG-1을
먼저 구현한다. TAG-3(조회)은 TAG-1과 별개로 시작할 수 있다(기존 노트를 여는 것만으로 확인
가능하므로 TAG-1의 "추가" 로직에 의존하지 않는다).

TAG-1은 의도적으로 **편집 모드(`!isCreating`)에서만** `TagInput`을 노출한다. 생성 모드
(`isCreating`)에서 `TagInput`을 노출하고 최초 저장 시 태그를 함께 반영하는 것은 TAG-4의
범위다 — 그렇지 않으면 TAG-1만 끝난 시점에 "생성 화면에서 태그를 추가해도 저장 시 조용히
사라지는" 어중간한 상태가 생긴다.

## TAG-1: 편집 중인 노트에 태그 추가

**설명**

노트 편집 화면(`NoteEditor`, `!isCreating`)에서 태그 입력창에 텍스트를 입력하고 Enter를
누르면 칩 형태로 태그가 추가된다. "저장" 버튼을 누르기 전까지는 로컬 상태에만 존재하고, 저장
시 `updateNote(id, { tags })`로 서버에 반영된다. "취소"를 누르면 추가한 태그도 함께 폐기된다.
`Note` 타입에 `tags: string[]` 필드를 추가하고, `src/components/TagInput.tsx`(입력창 + 칩
목록 UI)와 `src/utils/tags.ts`(trim/중복 판단 포함한 `addTag` 순수 함수)를 새로 만든다.
`TagInput`은 이 이슈에서는 편집 모드에서만 렌더링한다(생성 모드는 TAG-4에서 켠다).
(ADR-001, ADR-002, ADR-003 참고)

**완료 조건 (Acceptance Criteria)**

- **시나리오: 태그를 정상적으로 추가한다**
  - Given 사용자가 기존 노트를 선택해 편집 화면을 열었고, 태그 입력창이 비어 있다
  - When 입력창에 `react`를 입력하고 Enter를 누른다
  - Then 입력창 아래(또는 옆)에 `react` 칩이 나타나고, 입력창은 다시 빈 상태가 된다
- **시나리오: 이미 태그가 하나 있는 노트에 새 태그를 추가한다**
  - Given 노트에 이미 `study` 태그 하나가 있다
  - When 태그 입력창에 `urgent`를 입력하고 Enter를 누른다
  - Then 기존 `study` 칩은 그대로 남아 있고, `urgent` 칩이 추가로 나타나 총 2개의 칩이 보인다
    (기존 태그가 새 태그로 대체되지 않는다)
- **시나리오: 태그는 저장 전까지 서버에 반영되지 않는다**
  - Given 사용자가 태그 입력창에 `todo`를 입력하고 Enter로 추가했다
  - When 아직 "저장" 버튼을 누르지 않은 상태에서 네트워크 요청을 확인한다
  - Then `updateNote`/`createNote` API 호출이 발생하지 않는다
- **시나리오: 저장 시 추가한 태그가 서버에 반영된다**
  - Given 편집 중인 기존 노트에 `todo` 칩을 추가했다
  - When "저장" 버튼을 클릭한다
  - Then `updateNote(id, { tags: [...기존 태그, 'todo'] })`가 호출되고, 성공 후 화면의 노트
    데이터에 `todo`가 포함된다
- **시나리오: 태그 추가 후 취소하면 추가한 태그가 사라진다**
  - Given `study` 태그만 있는 노트를 열고, `urgent` 칩을 새로 추가했다
  - When "취소" 버튼을 클릭한다
  - Then 편집 화면이 닫히고 `updateNote` API는 호출되지 않는다
  - And 같은 노트를 다시 열면 `study` 태그만 있고 `urgent`는 없다
- **시나리오: 대소문자/공백만 다른 중복 태그는 추가되지 않는다**
  - Given 노트에 이미 `React` 태그가 있다
  - When 입력창에 `react `(뒤에 공백 포함)를 입력하고 Enter를 누른다
  - Then 새 칩이 추가되지 않고, 기존 `React` 칩 표기도 그대로 유지된다
- **시나리오: 빈 입력은 조용히 무시된다**
  - Given 태그 입력창이 비어 있거나 공백만 있다
  - When Enter를 누른다
  - Then 아무 칩도 추가되지 않고, 에러 메시지도 표시되지 않는다 (`console.error` 호출 없음)
- **시나리오: 태그 개수/길이에 제한이 없다**
  - Given 노트 편집 화면이 열려 있다
  - When 서로 다른 태그를 20개 연속으로 추가한다
  - Then 20개 칩이 모두 정상적으로 추가되고, 어떤 경고나 차단도 발생하지 않는다
- **시나리오: 생성 모드에서는 아직 태그 입력창이 보이지 않는다**
  - Given 사용자가 "+ 새 노트"를 눌러 생성 화면(`isCreating=true`)을 열었다
  - When 화면을 확인한다
  - Then 태그 입력창이나 칩 목록이 보이지 않는다 (TAG-4 완료 전까지는 편집 모드 전용)

## TAG-2: 편집 중인 노트에서 태그 삭제

**설명**

TAG-1에서 추가된 태그 칩 각각에 삭제(×) 버튼을 붙이고, 클릭 시 해당 태그를 로컬 태그 목록에서
제거한다. 삭제도 추가와 동일하게 "저장" 시점에만 서버에 반영되고, "취소" 시 폐기된다.

**완료 조건 (Acceptance Criteria)**

- **시나리오: 칩의 × 버튼으로 태그를 삭제한다**
  - Given 편집 중인 노트에 `react`, `todo` 두 개의 태그 칩이 있다
  - When `react` 칩의 × 버튼을 클릭한다
  - Then `react` 칩은 화면에서 사라지고 `todo` 칩만 남는다
- **시나리오: 삭제도 저장 전까지는 서버에 반영되지 않는다**
  - Given `react` 칩의 × 버튼을 클릭해 화면에서 제거했다
  - When 아직 "저장" 버튼을 누르지 않았다
  - Then `updateNote` API 호출이 발생하지 않는다
- **시나리오: 저장 시 삭제한 태그가 서버에 반영된다**
  - Given `react`, `todo` 태그가 있는 노트에서 `react` 칩을 삭제했다
  - When "저장" 버튼을 클릭한다
  - Then `updateNote(id, { tags: ['todo'] })`가 호출되고, 성공 후 화면에 `react`가 더 이상
    보이지 않는다
- **시나리오: 태그 삭제 후 취소하면 삭제한 태그가 그대로 남아 있다**
  - Given `study`, `urgent` 태그가 있는 노트를 열고, `urgent` 칩을 삭제했다(화면에서만)
  - When "취소" 버튼을 클릭한다
  - Then `updateNote` API는 호출되지 않는다
  - And 같은 노트를 다시 열면 `study`, `urgent` 태그가 그대로 남아 있다
- **시나리오: 태그가 하나도 없는 상태로 저장할 수 있다**
  - Given 노트에 태그가 1개만 있고, 그 칩을 삭제해 태그가 0개가 됐다
  - When "저장" 버튼을 클릭한다
  - Then `updateNote(id, { tags: [] })`가 호출되고 에러 없이 저장된다

## TAG-3: 노트 상세 화면에서 태그 목록 조회 (기존 노트 포함)

**설명**

노트를 선택해 편집 화면을 열면, 그 노트에 이미 저장된 태그가 칩 목록으로 표시된다.
`db.json`의 기존 노트처럼 `tags` 필드 자체가 없는 노트도 에러 없이 "태그 없음"으로 표시되어야
한다(`selectedNote.tags ?? []`). 태그는 사이드바 노트 목록(`NoteItem`)에는 표시하지 않는다.

**완료 조건 (Acceptance Criteria)**

- **시나리오: 태그가 있는 노트를 열면 태그가 보인다**
  - Given `react`, `study` 태그가 저장된 노트가 있다
  - When 사이드바에서 그 노트를 클릭해 편집 화면을 연다
  - Then `react`, `study` 두 개의 칩이 태그 영역에 표시된다
- **시나리오: 태그 필드가 없는 기존 노트를 열어도 에러가 나지 않는다**
  - Given `db.json`에 `tags` 필드 자체가 없는 노트가 있다 (마이그레이션 이전 데이터)
  - When 그 노트를 클릭해 편집 화면을 연다
  - Then 에러 없이 화면이 렌더링되고, 태그 영역은 빈 상태(칩 없음)로 보인다
- **시나리오: 노트를 바꿔가며 선택해도 태그 목록이 올바르게 동기화된다**
  - Given `react` 태그가 있는 노트 A와 태그가 없는 노트 B가 있다
  - When 노트 A를 열었다가 다시 노트 B를 클릭한다
  - Then 노트 A의 `react` 칩이 남아있지 않고, 노트 B의 태그 영역은 비어 있다
- **시나리오: 사이드바 노트 목록에는 태그가 표시되지 않는다**
  - Given 여러 태그가 달린 노트가 목록에 있다
  - When 사이드바 노트 목록(`NoteList`/`NoteItem`)을 확인한다
  - Then 제목/미리보기/날짜만 보이고, 태그 칩이나 배지는 어디에도 표시되지 않는다

## TAG-4: 새 노트 생성 시 태그와 함께 저장

**설명**

"+ 새 노트"로 노트를 생성하는 화면에서도 TAG-1의 `TagInput`을 노출하도록 켜고, 최초 "저장" 시
제목/내용과 함께 태그도 한 번에 서버에 반영한다. `NotesContext.createNote(title, content)`를
`createNote(title, content, tags)`로 확장한다. (ADR-003 Consequences 참고)

**완료 조건 (Acceptance Criteria)**

- **시나리오: 생성 모드에서 태그 입력창이 노출된다**
  - Given "+ 새 노트" 버튼을 눌러 생성 화면을 열었다
  - When 화면을 확인한다
  - Then 편집 모드와 동일하게 태그 입력창과 칩 목록 영역이 보인다 (TAG-1의 편집 모드 전용
    제한이 여기서 해제됨)
- **시나리오: 새 노트를 태그와 함께 최초 저장한다**
  - Given 생성 화면에서 제목 `회의록`, 태그 `work`, `2026Q1`을 입력했다
  - When "저장"을 클릭한다
  - Then `createNote(title, content, tags)`가 `tags: ['work', '2026Q1']`을 포함해 호출되고,
    생성된 노트가 목록에 나타난다
- **시나리오: 태그 없이도 새 노트를 저장할 수 있다**
  - Given 생성 화면에서 제목만 입력하고 태그는 하나도 추가하지 않았다
  - When "저장"을 클릭한다
  - Then `createNote`가 `tags: []`로 호출되고 에러 없이 노트가 생성된다
- **시나리오: 생성 직후 편집 화면을 다시 열면 방금 추가한 태그가 보인다**
  - Given 태그 `work`를 포함해 새 노트를 저장했다
  - When 방금 생성된 노트를 사이드바에서 다시 클릭한다
  - Then 편집 화면에 `work` 칩이 표시된다 (TAG-3의 조회 동작과 연결)
- **시나리오: 새 노트 작성 중 태그를 추가하고 취소하면 노트 자체가 생성되지 않는다**
  - Given 생성 화면을 열고 태그 `draft`를 추가했다
  - When "취소" 버튼을 클릭한다
  - Then `createNote` API는 호출되지 않고, 노트 목록에 새 노트가 생기지 않는다
