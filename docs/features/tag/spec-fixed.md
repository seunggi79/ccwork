# 태그 기능 정의서 (확정)

`spec-original.md`의 기본 요구사항을 바탕으로 데이터 구조/UI 패턴/엣지케이스를 확정한 문서.
"질문 1~7"은 사용자와 논의해 확정한 항목이고, "추가 결정 사항"은 스펙에 없어 구현 시 반드시
필요한데 별도 질문 없이 기존 프로젝트 관례(CLAUDE.md)에 맞춰 임의로 확정한 항목이다.

## 기능 개요

노트에 태그를 추가/삭제하고, 노트 상세(편집) 화면에서 태그 목록을 확인할 수 있다.

## 확정된 결정 사항 (질문 1~7)

1. **데이터 구조**: 별도 `tags` 컬렉션을 두지 않고, `Note.tags: string[]`로 노트 객체에 직접
   내장한다.
2. **태그 추가 UI**: 자유 텍스트 입력 후 Enter로 추가하는 방식(칩 + 개별 삭제 버튼). 자동완성/
   기존 태그 재사용 UI는 없다.
3. **저장 시점**: 태그 추가/삭제는 `title`/`content`와 동일하게 로컬 state로만 반영되고, "저장"
   버튼 클릭 시 한 번에 `updateNote`/`createNote` 호출로 서버에 반영된다. "취소" 시 태그 변경도
   함께 폐기된다.
4. **중복 판단 기준**: `trim()` 후 대소문자 무시(`toLowerCase()`)로 비교해 중복이면 추가하지
   않는다. 최초 입력한 원본 표기(대소문자)를 그대로 저장한다.
5. **빈 입력 처리**: 공백만 있거나 빈 문자열인 입력은 조용히 무시한다 (에러 로그 없음, 입력창
   유지).
6. **개수/길이 제한**: 노트당 태그 개수, 태그 문자열 길이 모두 제한을 두지 않는다.
7. **노출 범위**: `NoteEditor`(노트 상세/편집 화면)에만 태그를 표시한다. 사이드바 목록
   (`NoteItem`/`NoteList`)에는 태그를 표시하지 않는다.

## 추가 결정 사항 (질문 없이 확정)

프로젝트의 기존 패턴을 그대로 따르는 세부 구현 결정이라 별도 질문 없이 확정.

- **타입 정의**: `src/types/note.ts`의 `Note` 인터페이스에 `tags: string[]` 필드를 추가한다
  (옵셔널이 아닌 필수 필드로 선언 — 런타임에서는 아래 하위 호환 처리로 항상 배열을 보장한다).
- **하위 호환 (엣지케이스)**: `db.json`의 기존 노트들은 `tags` 필드가 없다. `NoteEditor`가
  노트를 폼에 동기화할 때 `selectedNote.tags ?? []`로 다뤄 태그가 없는 기존 노트도 에러 없이
  빈 태그 목록으로 표시되게 한다.
- **API 계층 (`src/api/notes.ts`)**: `createNote`/`updateNote`는 이미 `Note`의 임의 필드를
  받는 구조(`Omit<Note, 'id' | 'createdAt' | 'updatedAt'>`, `Partial<Note>`)라 시그니처 변경이
  필요 없다. `tags`는 다른 필드와 동일하게 요청 본문에 그대로 실린다.
- **Context 계층 (`src/context/NotesContext.tsx`)**: `createNote(title, content)` 시그니처를
  `createNote(title, content, tags)`로 확장한다 (API 함수명과 Context 메서드명 1:1 매칭 규칙
  유지, 파라미터만 추가).
- **컴포넌트 구조**: 태그 입력 UI(텍스트 입력 + 칩 목록)는 별도 컴포넌트로 추출하지 않고
  `NoteEditor` 내부에 인라인으로 구현한다. 현재 `NoteEditor`가 title/content 입력도 별도
  컴포넌트로 분리하지 않은 패턴과 일관되며, 이 기능만을 위한 조기 추상화를 피한다.
- **네이밍**: 로컬 상태는 `tags`(추가된 태그 배열), `tagInput`(입력 중인 텍스트)로, 핸들러는
  `handleAddTag`/`handleRemoveTag`로 명명한다 (prop `onX` / 구현 `handleX` 규칙과 별개로,
  이 두 핸들러는 콜백 prop이 아닌 내부 로컬 이벤트 핸들러이므로 `handleX` 네이밍만 적용).
- **삭제 실패 처리**: 태그 관련 에러(태그 자체의 추가/삭제 실패는 로컬 state 조작이라 실패
  케이스가 없음)는 해당 없음. 저장 실패 시의 에러 처리는 기존 `handleSave`의
  `console.error('저장에 실패했습니다', e)` 흐름을 그대로 사용한다 (alert 없음).
- **스타일링**: 태그 칩은 기존 버튼 스타일(`bg-muted`, `text-muted-foreground`, `rounded-xl`)과
  통일감 있게 pill 형태(`rounded-full`)의 작은 배지로, 각 칩에 삭제(x) 버튼을 포함한다. 새로운
  디자인 토큰을 추가하지 않고 `index.css`의 기존 `@theme` 토큰만 사용한다.

## Out of Scope (이번 구현에서 하지 않는 것)

- 태그 자동완성/기존 태그 재사용 UI
- 태그로 노트 필터링/검색
- 태그 개수/길이 제한
- 사이드바 노트 목록(`NoteItem`)에 태그 배지 표시
- 태그 이름 변경, 태그별 색상 지정 등 태그 자체를 독립 엔티티로 관리하는 기능
