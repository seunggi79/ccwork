# YEEZY 디자인 시스템 (노트 앱 적용판)

이 노트 앱의 **모든 스타일 작업은 이 디렉토리(`docs/design-system/`)를 먼저 참고**한 뒤
진행한다. 컴포넌트에 클래스를 추가/변경하거나 `src/index.css`의 토큰을 건드리는 작업을 시작하기
전에, `design-system` 스킬(`.claude/skills/design-system/SKILL.md`)을 통해 관심사에 맞는
파일을 확인할 것 (아래 "파일 구성" 참고).

## 출처

Claude Design에서 생성한 "YEEZY Design System" — yeezy.com을 모델로 한 **브루탈-럭셔리
미니멀리즘** 비주얼 레퍼런스 브리프. 실제 코드베이스나 Figma 파일이 아니라 서면 디자인 브리프가
원본이므로, 이 문서는 그 브리프를 이 노트 앱(전자상거래가 아닌 CRUD 노트 앱)의 맥락에 맞게
재해석한 것이다. 원본 브리프에만 있고 이 앱에는 없는 개념(제품 사진, 사이즈 선택, 체크아웃 흐름
등)은 각 문서에서 "Out of Scope"로 명시적으로 배제했다.

## 핵심 철학

- **인터페이스는 상점이 아니라 시스템 유틸리티/터미널처럼 동작한다.** 장식이 아니라 기능이
  화면을 채운다.
- **순백 캔버스 + 순흑 UI.** 크로매틱 컬러는 원칙적으로 없다.
- **단일 서체.** 모노스페이스 한 벌로 모든 텍스트를 통일한다. 위계는 크기/굵기가 아니라
  **위치와 여백**으로 만든다.
- **하드엣지.** 라운드 코너, 그림자, 그라디언트, 블러 없음. 깊이는 여백만으로 암시한다.
- **침묵이 곧 럭셔리.** 과장된 문구, 이모지, 설득형 카피가 없다. 담백하고 사무적인 톤.
- **상태는 반전(inversion)과 투명도로 표현한다.** 색상 변화나 스케일 변화가 아니라 흑/백 반전,
  40–55% 투명도로 hover/press를 표현한다.

## Substitutions & caveats (이 앱에 맞춘 대체/예외 사항)

원본 브리프의 "Substitutions & caveats" 관례를 그대로 이어받아, 이 앱에 적용할 때 원본 그대로
따를 수 없는 지점을 여기에 명시한다.

- **폰트 — 라이선스 대체.** 원본은 YZY Plex Mono(라이선스 IBM Plex Mono 파생)를 쓰지만 바이너리가
  없으므로 IBM Plex Mono(Google Fonts)를 근사 대체제로 쓴다.
- **폰트 — 한글 미지원 (이 앱 고유의 캐비어트).** IBM Plex Mono는 한글 글리프가 없다. 이 앱은
  CLAUDE.md 규칙상 UI 텍스트가 한국어이므로, 한글 body 텍스트에는 한글을 지원하는 모노스페이스
  폰트를 폴백으로 반드시 지정해야 한다. 후보: D2Coding, Noto Sans Mono CJK KR, Coding Font 계열.
  **최종 폰트 선정은 TBD** — 실제 적용(코드 반영) 시점에 확정한다. 이 문서는 방침만 정한다:
  라틴/숫자는 IBM Plex Mono, 한글은 한글 지원 모노스페이스 폴백으로 렌더링한다.
- **대문자화 · 브랜드 보이스 — 한국어 유지 (원본과 다른 결정).** 원본은 UI 텍스트 자체를 영어
  대문자로 쓰는 것이 브랜드 보이스의 핵심이지만, 이 앱은 CLAUDE.md의 한국어 UI 텍스트 규칙을
  그대로 유지한다. 즉:
  - 한글 UI 텍스트(예: "저장", "취소", "제목을 입력해주세요")는 **원문 그대로 한국어**로 쓰고,
    대문자 변환을 적용하지 않는다 (한글은 대소문자 개념이 없음).
  - 대문자화는 라틴 문자·숫자로 된 요소(날짜의 영문 월 표기, 상태 코드, 향후 추가될 영문 라벨
    등)에만 적용한다.
  - 브루탈리즘의 "자간으로 만드는 리듬"은 한글에도 적용 가능하므로, 한글 라벨에도 넓은
    자간(tracking)은 그대로 쓴다 (`tracking-widest` 등 — 기존 `NoteList`/`NoteEditor`의 eyebrow
    라벨 패턴이 이미 이 방향과 일치한다).
- **Destructive 컬러 — 실용적 예외 (원본에 없는 규칙).** 원본은 제품 사진 외 크로매틱 컬러가
  전혀 없는 완전 모노크롬이지만, 이 앱은 노트 삭제처럼 되돌릴 수 없는 액션을 사용자에게 명확히
  경고해야 한다. 따라서 **`--color-destructive`(red)를 실용적 예외로 유지**한다. 단, 사용
  범위는 삭제 액션의 hover/텍스트 색상 등 최소한으로 제한하고, 다른 곳(정보성 강조, 브랜드
  포인트 등)에는 색을 쓰지 않는다.
- **제품 이미지 관련 캐비어트는 Out of Scope.** 원본의 `ProductTile` 이미지 컷아웃 관련 내용은
  이 앱에 해당 사항이 없어 제외한다.

## 파일 구성

관심사별로 토큰 값과 Do/Don't를 한 파일에 모아뒀다 (값 따로, 규칙 따로 찾아다니지 않도록).

- **[`colors.md`](./colors.md)** — 컬러 토큰 값 + Do/Don't.
- **[`typography.md`](./typography.md)** — 폰트/사이즈/자간 토큰 값 + Do/Don't (한글 처리 포함).
- **[`spacing.md`](./spacing.md)** — 여백 스케일 + Do/Don't.
- **[`borders-shadows.md`](./borders-shadows.md)** — 보더/라운드/섀도우 값 + Do/Don't.
- **[`motion.md`](./motion.md)** — 트랜지션/hover/press 값 + Do/Don't.
- **[`components.md`](./components.md)** — 아이콘 + Button/IconButton/Input/StatusLabel/Modal/
  태그칩 등 실제 존재·계획된 컴포넌트별 Do/Don't.
- **[`content-voice.md`](./content-voice.md)** — 화면에 노출되는 문구를 쓸 때의 톤 Do/Don't.

Claude Code에서는 이 인덱스를 매번 전부 읽는 대신, `design-system` 스킬
(`.claude/skills/design-system/SKILL.md`)이 "하려는 작업 → 읽을 파일" 내비게이션을 제공한다.

## 적용 범위 안내

이 문서들은 **문서화만** 다룬다. `src/index.css`의 `@theme` 토큰이나 `NoteItem`/`NoteEditor`/
`Layout` 등 실제 컴포넌트 코드는 아직 이 시스템에 맞춰 변경되지 않았다. 이후 스타일 작업(신규
기능의 UI 구현, 기존 컴포넌트 리스타일링 등)을 할 때 이 문서를 기준으로 진행한다.
