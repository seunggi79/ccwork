📝 notes-app 아키텍처

React 19 + TypeScript + Vite 노트 앱의 src/ 디렉토리를 분석해 생성한 구조도입니다.

총 3개의 다이어그램: ① 컴포넌트 의존성 그래프, ② 상태 소유권/흐름, ③ 저장 동작 시퀀스.

① 컴포넌트 의존성 그래프

src/ 하위 모든 모듈의 import 관계입니다. 실선은 렌더링(하위 컴포넌트로 사용), 점선은 훅을 통한 상태 구독 또는 타입 import를 의미합니다.

② 상태 소유권 & 흐름

"서버 상태는 Context, UI-only 상태는 지역 state" 원칙에 따라 상태가 어디서 소유되고 어떤 경로로 컴포넌트에 전달되는지 표현합니다.

③ 저장 동작 시퀀스 (예: 노트 저장)

NoteEditor.handleSave가 호출된 시점부터 화면이 갱신되기까지의 실제 흐름입니다. 낙관적 업데이트 없이 서버 응답을 받은 뒤에만 로컬 상태를 갱신합니다. 

sequenceDiagram
    participant U as 사용자
    participant NE as NoteEditor
    participant CTX as NotesContext
    participant API as api/notes.ts
    participant DB as json-server(db.json)

    U->>NE: 제목/내용 입력 후 저장 클릭
    NE->>NE: 제목 검증
    alt 제목이 비어있음
        NE->>NE: console.error() 후 중단
    else 검증 통과
        NE->>CTX: createNote(title, content) 또는
updateNote(id, updates)
        CTX->>API: createNote() / updateNote()
        API->>DB: POST /notes 또는 PATCH /notes/:id
        DB-->>API: 저장된 note 응답
        API-->>CTX: note 반환
        CTX->>CTX: setNotes()로 로컬 상태 갱신
(서버 응답 기반, 낙관적 업데이트 아님)
        CTX-->>NE: Promise resolve
        NE->>NE: onDone() 호출
        CTX-->>NE: 재렌더링 (최신 notes 반영)
    end
